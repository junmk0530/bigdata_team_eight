## 2. 진행 결과 (근거)

**데이터셋:** UCI Machine Learning Repository News Aggregator (2014-03-10 ~ 2014-08-10, public domain)

- 여러 매체가 같은 사건을 다룬 제목이라 이번 과제에 맞다.
- 기사 본문은 쓰지 않는다. 제목, 출처, URL, 분야, 시각만 사용한다.
- 같은 사건 제목이 2개 이상인 사건만 남기고 사건당 최대 6개로 잘랐다. 시드는 20261118이다.
- 실험 샘플은 제목 1,500개, 사건 253개다. 웹 첫 화면은 그중 480개, 80개 사건이다.
- 사용자 열람 이력은 데이터셋에 넣지 않는다. 관심 분야와 북마크는 서비스가 따로 저장한다.

**전처리와 형식:** `docs/DATA.md`

- NFKC, 소문자, 단어 집합, 불용어 제거 후 Jaccard를 계산한다.
- 입력은 `title`/`headline`, `source`, `category`, `date`, `url`이다.
- 그룹 결과는 `NewsGroup` 필드로 고정했다.

**정답 비교:** `docs/EXPERIMENT.md`

- 1,500개 제목의 전체 쌍은 1,124,250개다. Jaccard 0.40 정답 쌍은 422개이고, 전체 쌍 계산은 244ms였다.
- 현재 서비스인 128차원 MinHash, 64밴드 × 2행은 후보 8,000쌍, Precision 5.3%, Recall 100%, 비교 횟수 99.3% 감소, 후보 생성 157ms였다.
- 32밴드 × 4행은 Precision 43.0%, Recall 83.4%다. 16밴드 × 8행은 Precision 92.7%, Recall 21.1%다.
- 서비스는 후보를 Jaccard로 다시 거르므로 기본값은 Recall이 높은 64밴드 × 2행을 유지한다.
- UCI 같은 사건 쌍 3,725개 중 Jaccard 0.40 이상인 쌍은 402개다. 제목이 다르면 같은 사건도 대부분 놓친다.

**웹:** 첫 화면이 `public/data/headlines.json`을 읽어 같은 파이프라인으로 묶는다. 확인 결과는 제목 480개, 사건 389개, 기사 2건 이상 그룹 49개다. 공유 DB의 가상 샘플은 목록에 남아 있고, 첫 화면을 덮어쓰지 않는다. 파일을 읽지 못하면 기존 가상 샘플로 돌아간다.

**요약 에이전트:** Z.ai Chat Completions를 우선 사용하도록 연결했다. 키와 모델이 없으면 기존 OpenAI Responses 경로를 쓰고, 둘 다 없으면 제목 키워드 요약만 보여 준다. 로컬과 이번 제출 시점에는 `ZAI_API_KEY`가 없어 실제 호출은 하지 않았다.

## 3. 문제점 및 이슈

- Z.ai 키와 모델이 없다. 사용량과 비용을 확인하기 전에는 실호출을 하지 않는다. 문서상 경량 예는 `glm-5.3-flash`다.
- 1,500건에서는 전체 쌍 계산과 LSH 시간의 차이가 작다. 비교 횟수 감소와 시간 감소를 같은 수치로 말하면 안 된다.
- 제목 단어 집합은 표현이 다른 같은 사건을 대부분 묶지 못한다.
- 원본 분야에 Politics, World, Sports가 없어 화면의 해당 관심 분야는 이 샘플에서 비어 있다.
- 팀 문서 히스토리와 앱 코드 히스토리가 달랐다. 이번 병합에서 문서와 코드를 한 저장소에 둔다.

## 4. 다음 주 계획

- Z.ai 비용 확인 후 키를 넣고, 실제 그룹 몇 개의 요약 문장을 검토한다.
- 5,000건에 가까운 샘플에서 64밴드 × 2행과 32밴드 × 4행의 시간과 Recall을 다시 비교한다.
- 제목만으로 놓치는 같은 사건을 보고서에 사례로 남긴다.
- 공유 DB 게시와 열람 이력 추천은 요약 품질 확인 뒤에 진행한다.
